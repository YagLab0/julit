JuLit · Plan de pivote

De microauditorías a liquidación
atómica de lotes (RWA / DvP)

Directorio industrial B2B + protocolo de entrega-contra-pago sobre Solana Devnet. El lote se tokeniza como NFT en escrow, se liquida en una transacción atómica en USDC y se redime (burn) al confirmarse la entrega física.
SOLANA DEVNET ANCHOR 0.32.1 NEXT.JS 16 · SUPABASE OCT 2026
01 · El nuevo ciclo de vida

Cinco pasos, tres de ellos on-chain

off-chain
Descubrimiento
Directorio B2B: origen, capacidad, pureza de planta. Deal privado entre empresas.
on-chain
create_lot
Lot PDA + NFT Metaplex (supply 1) minteado al escrow del PDA. Comprador reservado.
on-chain · DvP
settle_lot
USDC comprador → minera (− take rate a treasury) + NFT escrow → comprador. Atómico.
off-chain
Entrega física
Logística, aduana y recepción del cargamento. Fuera del protocolo.
on-chain
redeem_lot
El comprador firma recepción: burn del NFT + status Redeemed. Rastro permanente.

Estados del Lot PDA: Listed (NFT en escrow) → Settled (DvP ejecutado) → Redeemed (NFT quemado). El burn no borra el historial: mint, pago, transferencia y redención quedan verificables.

02 · Decisiones cerradas
NFT del lote
Metaplex Token Standard (NonFungible)
Mint + metadata + master edition creados por el programa vía CPI; update authority = Lot PDA.
Moneda de liquidación
Mint propio dUSDC en Devnet
6 decimales, airdrop a wallets demo desde el seed. Control total, sin faucets.
Rol auditor
Eliminado por completo
La certificación pasa a nivel planta: PDF + SHA-256 declarado por el producer, verificación pública por hash.
Compra
Solo lotes reservados
Todo lote nace con comprador designado; no hay compra spot ni góndola abierta.

04 · Supabase

Schema reescrito en el lugar

  • batches → lots: fuera campos de auditoría; dentro mint_address, settle_tx_signature, redeem_tx_signature, status listed|settled|redeemed.
  • company_type: producer | buyer. El producer carga certificado de planta (PDF + hash).
  • company_contracts: solo dirección buyer → producer.
  • Bucket audit-certificates → plant-certificates (mismas políticas).
05 · API

Índice verificado por RPC

  • borrar /certify, /certificate, /complete.
  • nuevo POST /api/lots, /settle, /redeem — cada ruta fetchea la tx por RPC y valida programa, cuentas, signer y éxito antes de escribir el índice.
  • nuevo POST /api/companies/plant-certificate — PDF content-addressed, hash recomputado server-side.
06 · Frontend

Transacciones reales en vez de firmas falsas

  • borrar /audit/* completo (dashboard, certify, inbox de contratos).
  • modificar alta de lote: sin auditor, comprador reservado obligatorio, firma create_lot.
  • modificar compra en modal de origen: visible solo al comprador designado, firma settle_lot (hoy genera una firma base58 aleatoria).
  • nuevo “Confirmar recepción” del buyer → redeem_lot con burn.
  • modificar passport público: timeline del ciclo, mint, links a settle/burn, verificación de cert de planta.
  • Dep nueva: @solana-program/token para derivar ATAs en el browser.
07 · Docs y narrativa

Lenguaje del nuevo modelo

  • GLOSSARY: out Auditor / Audit Certificate / ESG / EU assessment → in Lot, Digital Title, Escrow, DvP, Take Rate, Redemption, Plant Certification.
  • ADR-0002 (settlement simulado) superseded; ADRs nuevos: DvP atómico, título NFT + PDA de ciclo de vida, certificación de planta, lotes reservados, mint dUSDC.
  • Features *.feature reescritos; specs previos marcados superseded.
  • Landing + pitch: “Discover → Tokenize → Settle → Deliver → Redeem”.
Claims seguros para el jurado. “Elimina el riesgo de liquidación” — no “de contraparte”. El NFT es la representación digital de un derecho contractual sobre el lote, no título legal automático.
08 · Complejidad y orden de trabajo
1Programa + tests LiteSVM— el cuello de botella: CPI a Metaplex, mint PDA, escrow con PDA signer, split de fee
2DB + API— schema reescrito, verificación de tx por RPC, upload de cert de planta
3Frontend— alta / settle / redeem con txs reales, passport nuevo, borrado de /audit

Riesgos: pinning de mpl-token-metadata contra anchor 0.32 (resolver primero); tamaño de la tx de create_lot (fallback: instrucción split o v0 + LUT); el mint dUSDC y los ATAs de las wallets demo dependen del seed script; el push al proyecto Supabase linkeado descarta la data demo actual.

Estimación global: media-alta para contexto hackathon. Varias jornadas de foco; el riesgo está concentrado en el programa — DB, API y front son trabajo mecánico una vez definido el IDL.
