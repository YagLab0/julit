# Passport verification is staged: the index digest until certification exists on-chain

Verifying a certificate means downloading the PDF, hashing its bytes in the visitor's browser, and comparing the result against the digest recorded for the batch. It proves the document matches the recorded digest, not the truth of the auditor's findings, which remain attributed declarations ([ADR-0004](./0004-auditor-declarations-and-shared-evidence.md)).

The Anchor programme exists and registers batches on Devnet (`create_batch`), but it has no certification instruction and the batch account carries no certificate digest, so no on-chain digest can serve as the reference. Until they exist, the reference is the public index's `audit_sha256`, and the interface must name the source: the result states that the PDF matches the digest indexed for the batch, and that Solana verification arrives with certification on-chain. The comparison against the index is never presented as Solana verification, and the index JSON is never treated as canonical — the database contract's requirement that the certificate comparison read the batch's PDA describes the state once the certification instruction exists. The passport's record contrast against the PDA is a separate read that ships with the passport ([ADR-0010](./0010-passport-reads-the-on-chain-record.md)).

When the certification instruction lands and the PDA carries the digest, the reference becomes that digest — the behaviour the `@program` scenario of [public-catalogue-and-passport.feature](../features/public-catalogue-and-passport.feature) describes — while the client-side byte hashing and the visitor's flow stay the same.
