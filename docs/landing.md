# Public landing

The public `/` experience presents JuLit's B2B lithium-carbonate proposition in Spanish. It links to the existing `/batches` demo and `/sign-in` without introducing a new registration, payment, or verification flow.

## Presentation contract

The approved content and implementation acceptance live in the local landing specification and Spanish copy under `.scratch/landing/`. The final section order is hero, commercial problem/solution pairs, proposed Producer–Auditor–Buyer process, conceptual Passport, participant benefits, FAQ, and dark closing composition.

The landing owns a local light semantic-token boundary. It never changes the persistent `next-themes` preference or the application's global dark-mode class. The closing section owns an inverse surface within that same boundary. Existing application providers and demo behavior remain unchanged.

Substantive content is server-rendered. Native links and FAQ disclosures do not depend on the landing motion enhancement. The enhancement adds one-time Web Animations API entrances and pointer-only press feedback, uses the installed Emil design-engineering guidance, and cancels movement for keyboard activation and reduced-motion changes. No new animation or UI primitive dependency is required.

The three process stages include illustrative widgets: packaged lithium carbonate, an associated auditor report, and buyer Passport review. The industrial big bag uses the existing Three.js dependency, loaded only when the widget approaches the viewport, and rotates continuously with an 18-second revolution. The report writes its field rows and document lines progressively in a repeating 5.6-second cycle. The buyer Passport and review label float gently in repeating 5.2-second cycles. Loops pause offscreen and while the document is hidden, and resume when visible. Reduced motion restores complete static illustrations; keyboard input also stops widget movement until pointer interaction resumes it. Graphics resources and animations are disposed on unmount. A server-rendered SVG preserves the product illustration without JavaScript or WebGL, and after context loss. These widgets contain field categories, not fabricated records, audit results, or executed payments. The photographic hero and existing application flows remain unchanged.

The enhancement specification and ticket live under `.scratch/landing-process-widgets/`; this is the limited supersession of the original landing's no-3D constraint, not permission to load the application map.

The main “La evidencia de cada lote, en un solo lugar” Passport composition uses an editorial technical-document treatment: a restrained JuLit masthead, material formula, and six numbered rows with plain-language explanations. It contains origin/producer, quantity/purity, water/carbon footprint, auditor report, integrity reference, and Batch state. A narrow accent visits the six rows sequentially in an 8.4-second loop; text remains stationary and fully readable throughout. There are no nested field cards, loading/progress bars, stacked-paper decoration, or floating document. The shared motion controller provides visibility pausing, reduced-motion support, keyboard cancellation, and cleanup. All six fields remain server-rendered and accessible, while the animated accents are decorative. The conceptual disclaimer remains visible, and no real-looking values or audit outcomes are introduced.

The participant-benefit cards replace their static icons with two decorative diagrams on the landing's radial stage. The producer diagram keeps Origen and Evidencia in place while a current draws both into Estructura, alternating continuously every 2.4 seconds. The buyer diagram draws a line through Datos, Documentación, Evaluación, and Respaldo; each mark paints when the line reaches it and unpaints when the line retreats. Pendiente stays open, and a short mark approaches it without connecting. The buyer line travels for 2.6 seconds and reverses. Neither diagram rests in a frozen pose while visible. Loops pause offscreen and while the document is hidden. Reduced motion restores the complete static illustration. Keyboard input does not stop these two diagrams. They use category labels only: no quantities, Batch identifiers, audit results, or certification marks. Approved card copy stays authoritative and server-rendered; the diagrams are hidden from assistive technology.

The demo remains simulated: no USDC transfer or evidence of received funds is presented. The Passport composition contains field categories only, not a fabricated Batch, audit finding, hash, wallet, QR, or transaction. Document integrity is not proof of the report's truth or physical sample-to-shipment correspondence, and a Batch Passport is not an official EU battery passport or compliance guarantee.
